# Техническое задание LS-TZ-01
Версия 1.0 от 08.11.2026. Шваб Роберт Эдуардович, И13_24_11.
## 1 Введение
Library System — электронная библиотека АИС «Умный кампус», вариант 2.
## 2 Основания для разработки
Практические работы МДК 03.02. Ключевые документы проекта: ГОСТ 19.201-78,
ГОСТ Р ИСО/МЭК 25010-2015 и ISO/IEC/IEEE 12207:2026.
## 3 Назначение разработки
Приём PDF/EPUB/ZIP в карантин; каталог опубликованных образцов; контроль прав и безопасных путей.
## 4 Требования к программе
FR-01: Librarian загружает PDF, EPUB и ZIP; 201, Quarantined.
FR-02: Reader получает 403; нет / неверный токен — 401.
FR-03: Небезопасный архив не оставляет файлов.
FR-04: Проверка формата и структуры независимо от MIME.
FR-05: Размеры, количество записей и защита от распаковки.
FR-06: 3 загрузки в минуту на пользователя, затем 429.
FR-07: Серверное имя и параметризация поиска EF Core.
FR-08: Каталог скрывает чужой карантин; выдача только Published.
FR-09: Отказы заносятся в журнал без токена.
FR-10: Нет путей и stack trace в ответе, нет lab в Production.
Лимиты: книга 1 МиБ, входной файл 2 МиБ, multipart 2 МиБ + 64 КиБ; ZIP 12 записей,
распакованный объём 3 МиБ, коэффициент сжатия 200. Все записи проверяются до сохранения.
Среда: .NET 8 SDK, Visual Studio 2022, браузер. Данные SQLite и файлы размещаются в App_Data.
Случайные серверные токены лабораторных ролей выдаются только в Development с loopback.
Нет внешнего IdP, AV/CDR и автоматической публикации новых документов; они остаются в карантине.
## 5 Требования к программной документации
Исходники C#, листинги, README, матрицы, отчёты, схема DFD, TRX и реальные снимки интерфейса.
## 6 Технико-экономические показатели
Для демонстрации используются .NET, SQLite и общедоступные библиотеки. Продажи и денежная рентабельность не моделируются.
## 7 Стадии и этапы разработки
ТЗ → исходный пример → аудит и метрики → рефакторинг → тесты → проверка отчётности.
## 8 Порядок контроля и приёмки
Сборка без ошибок; все обязательные тесты Passed; нет записи при отказе ZIP; соблюдены роли.
Матрица требований в traceability.json, условия и порядок в test-plan.md.
Автоматический тест не подменяет решение преподавателя о принятии работы.
