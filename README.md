# МДК 03.02 — Library System
Шваб Роберт Эдуардович, И13_24_11. Вариант 2: электронная библиотека PDF/EPUB.

## Запуск в Visual Studio

Распакуйте архив целиком и откройте `LibrarySystem.sln` в Visual Studio 2022 на Windows 10/11.
Для сборки нужны .NET 8 SDK, рабочие нагрузки «Разработка классических приложений .NET» и
«ASP.NET и разработка веб-приложений». При первой сборке Visual Studio скачает пакеты NuGet.
Для показа интерфейса используется Microsoft Edge WebView2 Runtime.

В обозревателе решений раскройте `src`, щёлкните правой кнопкой по `Library.Desktop` и
назначьте его запускаемым проектом. Нажмите F5 или зелёную кнопку. Откроется окно
«Электронная библиотека — МДК 03.02», а API запустится внутри процесса приложения
на свободном локальном порту. Вкладки ПР 1–8 доступны в этом окне. Закрытие окна завершает API.

Вариант с браузером также доступен через профиль `Library.Api`. Для обычного показа
в Visual Studio используйте `Library.Desktop`. Подробности: [Visual Studio](docs/VisualStudio.md).

## Проверка вручную
Раздел Библиотека: выбрать Librarian, скачать собственный образец PDF по ссылке,
выбрать его в форме и нажать Загрузить книгу. Ожидается 201, Quarantined.
С ролью Reader повторить: 403. Новые файлы остаются в приватном карантине.
ПР 8 → Выполнить проверки API: 12 сценариев обращаются к настоящему работающему API.
ПР 6 показывает сохранённый результат тестов. Для нового прогона откройте обозреватель тестов Visual Studio и запустите Library.Tests.
47 случаев xUnit и 12 HTTP-сценариев пересекаются и не складываются в число независимых тестов.

## Структура и границы
Desktop — окно WinForms со встроенным WebView2; Core — правила файлов; Api — локальный сервер, контроллеры, FluentValidation, EF Core SQLite;
Tools — обработка матриц, Roslyn-анализатор, разбор TRX; tests — xUnit и FluentAssertions 6.12.2.
before — намеренно уязвимый исходный образец, не включён в сборку и HTTP-маршруты.
docs — ТЗ, методика испытаний, схема DFD и листинги в отчётах.
App_Data, bin, obj, .vs не добавляются в Git. Данные и токены пользователей не публикуются.
Учебная выдача ролей разрешена только в Development с loopback. Для внешнего размещения нужны
внешний IdP, HTTPS, AV/CDR и согласованная процедура публикации. Проверка сигнатуры не заменяет антивирус.
verification содержит исходные результаты, а не вручную набранные сообщения об успехе.
